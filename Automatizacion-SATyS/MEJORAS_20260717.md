## Causas raíz y correcciones

### 1. Carpetas de ZIP tratadas como trámites

`descubrir_descargas_procesables()` recorría todas las subcarpetas inmediatas de
`descargas/<REGISTRO>/`. Las carpetas extraídas de ZIP se enviaban de nuevo a
Partes 3 y 4 como si fueran registros.

**Corrección:** solo se procesan carpetas con un número de registro válido
`CRTNN-NNNNNN`. Las subcarpetas solo se consideran cuando contienen metadata
propia y el padre es un contenedor heredado sin metadata.

### 2. Registros distintos con el mismo folio

Cuando un Registro no existía todavía en la columna `1711`, el programa buscaba
por `Memo/Volante` y reutilizaba la primera fila del mismo folio. Esto hacía que
el segundo registro sobrescribiera al primero.

**Corrección:** la identidad de una fila es el número de Registro. Una fila del
mismo folio solo se reutiliza cuando su columna `1711` está vacía. Si contiene
otro Registro, se agrega una fila nueva.

### 3. Metadata parcial descartada

Si una carpeta no tenía PDF ni nombre de operador, `procesar_folio()` terminaba
antes de actualizar el maestro. Esto afectó, entre otros, a `CRT26-012075`.

**Corrección:** si existe un Registro CRT válido, se conserva y se escriben los
campos disponibles aunque el operador o PDF falten.

### 4. Rutas de `_sin_operador` no escritas

La columna `Ruta` solo se escribía cuando el cruce RPC era exitoso.

**Corrección:** todos los registros reciben una ruta relativa. Para los casos sin
operador se usa `_sin_operador\<REGISTRO o identificador>`.

### 5. Reconciliación final automática

Se agregó `reconciliar_tramites_desde_folios.py`. Después de generar
`Folios_Datos_Completos.xlsx`, el pipeline ahora:

- actualiza o agrega una fila por Registro;
- completa las columnas equivalentes del maestro;
- recalcula R001–R027 desde el asunto;
- completa todas las rutas;
- elimina únicamente filas fantasma simples;
- conserva notas manuales y columnas de SharePoint;
- crea un respaldo antes de sustituir `TrámitesCRT.xlsx`;
- guarda el Excel de forma atómica.

## Despliegue y UI

`scripts/instalar_linux_1am.sh` ahora:

- instala y levanta la UI/API por defecto;
- acepta `SATYS_PYTHON_BIN` para usar Python 3.11+ aunque `sudo` tenga otro PATH;
- inicia el servicio diario mediante `/usr/bin/bash`;
- inicia Uvicorn mediante `/usr/local/sbin/satys-api-start`, evitando `203/EXEC`;
- verifica que el puerto de la UI esté escuchando antes de terminar;
- elimina overrides antiguos creados para corregir versiones previas;
- usa `systemctl start --no-block` con `--run-now`.

Para omitir la UI deliberadamente se puede usar `--no-install-api`.

- Nuevo `reparar_id_solicitante.py`.
- Detecta `id_solicitante` ausente, vacío o null.
- Reconsulta solo metadata; no duplica documentos descargados.
- Checkpoint atómico por Registro para reanudar después de apagón.
- Sección **Reparar IDs** en la UI con inicio, reanudación, reinicio de cola, detención y log en vivo.
